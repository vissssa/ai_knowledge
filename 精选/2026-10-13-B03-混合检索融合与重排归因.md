# 2026-10-13 B03 混合检索、融合策略与重排归因

> **精选题**。来源：2026-10-13 每日训练 `Q-20261013-B03`（`../2026-10/2026-10-13-AI-Agent-面试训练.md`）。本题核心内容未作改写，仅在末尾补充精选元信息、复习节奏与延伸资料。

## 一、原题

### B03｜基础定义题｜RAG 与搜索｜`Q-20261013-B03`

> 企业知识问答 Agent 用向量召回取 top-50 拼进上下文，线上答案正确率只有 61%。四个候选方案：
>
> - **A.** 换成更大更强的 embedding 模型。
> - **B.** 加 BM25 做混合检索，两路结果融合后取 top-50，再上一路 cross-encoder 重排到 top-8。
> - **C.** 只做 query rewrite 与多查询扩展，不加稀疏检索，不加重排。
> - **D.** 直接把 top-8 塞进上下文，前 42 条丢掉。
>
> 请回答：
> 1. 稀疏检索（BM25 类）与密集检索各自**在什么情况下失效**？给出具体例子，而不是泛泛而谈。
> 2. 两路召回的分数怎么融合？为什么**分数归一化 + 加权求和**经常踩坑？**只用排名的融合（如 RRF）**规避了什么假设、又损失了什么？
> 3. 重排什么时候**收益有限或直接亏损**？召回不足时上重排会发生什么？
> 4. 上线后效果仍不达标，如何**分层归因**：召回缺失、切片错误、融合/重排错位、上下文位置未被利用、还是生成端问题？每层用什么指标判定？

**难度**：中高。**考察方向**：稀疏与密集的互补性、融合策略的隐含假设、两阶段漏斗的成本与延迟、以及最容易失分的**错误归因**。

## 二、完整参考答案

### 1. 考察点

1. **稀疏与密集检索的失效模式**必须具体到例子，而不是"一个语义一个字面"。
2. **融合策略背后的假设**：分数可比吗、分布稳定吗、需要校准吗。
3. **两阶段漏斗的成本与延迟账**：什么时候重排是纯亏损。
4. **分层归因能力**：能不能在指标层面判断问题出在哪一段。
5. **重排不能替代召回**这一基本认知。

### 2. 准确定义与适用边界

**稀疏检索（BM25 / TF-IDF 系）**：基于词项频率与逆文档频率的字面匹配。

- 强项：**稀有标识符的精确命中**——错误码 `ERR_4021`、零件号 `ADC-8812X`、法条编号、人名、版本号。这些恰恰是向量模型最容易糊掉的东西，因为它们在语义空间中彼此很近，却从不等价。
- 弱项：**同义、上位词、跨语言表述**。"怎么退款"与"申请退回款项"在词项上几乎不重叠。

**密集检索（向量语义检索）**：把 query 与文档映射到同一向量空间，按相似度检索。

- 强项：**语义泛化、表述变体、拼写模糊**。
- 弱项：**精确字符串与编号**（容易把 `V2` 与 `V3` 判为很近）、**罕见领域术语**（不在 embedding 训练分布内）、以及**否定与约束**（"不能用 X 的场景"与"如何使用 X"在向量上很近）。

因此二者是**互补失效**，不是新旧替代。混合检索的正当性来自失效模式的正交性，而不是"多一路总归好一点"。

**适用边界**：查询含大量精确标识符、或领域术语不在 embedding 训练分布中时，纯向量检索必然有洞；反之，纯描述性、同义变体多的语料，密集路优势明显。

### 3. 简洁示例

设备运维手册问答场景：

| Query | 稀疏（BM25） | 密集（向量） | 该依赖谁 |
|---|---|---|---|
| "ERR_4021 如何处理" | 精确命中，排第一 | 与 ERR_4022 / 4023 混淆 | 稀疏 |
| "设备很烫怎么办" | 词项不重叠则可能失效 | 稳定命中"过热保护"章节 | 密集 |
| "机型 ADC-8812X 的额定扭矩" | 型号与单位精确命中 | 可能召回 8812Y | 混合，且稀疏路加权 |
| "不能用高压水枪的部位" | 无法理解"不能" | 极易召回"如何清洗" | 两路都弱，需要改写或结构化过滤 |

融合策略分两类：

**分数融合（归一化加权求和）**：`score = α·norm(dense) + (1-α)·norm(sparse)`。它要求两路分数在**同一可比的尺度**上。BM25 的分数无上界、随文档长度与语料统计剧烈漂移；余弦相似度挤在 0~1 的窄区间。做 min-max 归一化会被离群值拉扯——一个异常高分就能把整批分布压缩到极小范围，于是 α 需要持续重新校准，今天调好的权重明天就失效。

**排名融合（RRF, Reciprocal Rank Fusion）**：`RRF_score(d) = Σ_i 1/(k + rank_i(d))`，`k` 常取 60。它**只吃排名不吃分数**，因此不要校准、不惧分布漂移。代价是丢掉了分数的"置信度差距"（第一名与第一百名的差异被压平成 `1/(k+1)` 与 `1/(k+100)`），在需要靠分数阈值做裁剪的场景里不够用。另一个实现细节：**只出现在某一路结果中的文档是否参与另一路的求和**，不同实现处理不一致，落地时必须明确写死。

### 4. 与相近概念的区别

| 概念 | 位置 | 输入规模 | 成本 / 延迟 | 主要失效 |
|---|---|---|---|---|
| 稀疏 / 密集召回 | 第一阶段 | 全库或分片级 | 低 | 各自模型固有的盲区 |
| 融合（Fusion） | 两路之间 | 两路 top-N | 极低（纯计算） | 融合假设错误导致负优化 |
| 重排（Rerank） | 第二阶段 | 20~100 条 | 高（cross-encoder 逐对推理） | 延迟与成本，且救不回召回缺失 |
| 切片（Chunking） | 索引之前 | 全量文档 | 一次性 | 切片破坏语义，后续环节无法补救 |

关键认知：**重排是排序变换，不是召回补充。** 如果正确片段不在 top-50 里，再强的 cross-encoder 也找不出来——它只能给已有候选重新排序。题中方案 D（只留 top-8）的危险正在于此：它把"可能有用的第七名候选"直接丢弃，把 recall 上限压死在 top-8。

### 5. 在 AI Agent 系统中的典型应用

- **检索即工具**：RAG 是 Agent 最常见的工具调用之一。混合检索 + 重排是标准的两级漏斗（召回 50 → 重排 8 → 进上下文）。
- **延迟必须按候选数计算**：cross-encoder 要对每个 (query, doc) 对做一次完整前向传播，50 个候选就是 50 次推理。若整条链路延迟预算 800ms，重排可能占掉 300-500ms。压缩手段包括：候选从 50 降到 20、使用蒸馏过的小重排模型、设置 200ms 硬超时并降级为融合排名、以及只对"高价值查询"重排。
- **归因分层**是本题最值钱的部分：

| 层 | 症状 | 判定指标 | 典型原因 |
|---|---|---|---|
| 召回缺失 | 正确文档不在任何一路的 top-N 中 | Recall@50（两路并集后） | 切片破坏语义、embedding 与领域不匹配、元数据过滤过严 |
| 排序错位 | 在 top-50 但没进 top-8 | Recall@8 / MRR / nDCG@8 | 融合权重错误、重排缺位、重排模型不适配领域 |
| 上下文失效 | 正确片段进入上下文但答案仍错 | 位置分布与"中间丢失"人工抽检 | 片段位置靠中、多条片段互相干扰、系统指令与片段冲突 |
| 生成 / 可信问题 | 上下文中有答案但模型没用 | Groundedness、引用命中率 | 模型依赖先验、缺少引用约束、不确定时未被要求澄清 |

**归因顺序必须是：先验召回，再验排序，最后才怀疑模型。** 多数团队直接跳到"换个更大的模型"，而答案早在召回阶段就丢了。

### 6. 常见误区或错误用法

1. **召回不足靠重排救**：这是最烧钱的方向性错误，付出数倍延迟却动不了根因。
2. **把两路分数直接相加而不做验证与校准**：结果通常是 BM25（分数量纲巨大）事实上拿到了接近全部的权重，另一路被完全掩盖。
3. **把 RRF 当成数学最优融合**：它是鲁棒的启发式（用排名对抗分布漂移），不是最优；需要置信度信息的场景应回到校准过的分数融合。
4. **换了 embedding 却不重建索引**：维度或模型变了必须全量重建，否则索引里混着两个不同空间的向量。
5. **把 top-50 全塞进上下文**：既费钱又拉低效果（中间位置利用率低）；正确做法是重排压缩到 top-8，并在系统提示里明确"证据不足就追问或说明缺失"。
6. **不做分层指标就上 A/B**：出问题时聚合指标除了告诉你"整体掉了 3%"之外毫无定位价值。

### 7. 面试现场参考回答（1-2 分钟）

> 我选 B，但不会砍掉 C，也不会立刻做 A。
>
> 理由是这里的失效模式高度分叉：错误码、零件号、指令编号这类精确标识符，在向量检索里会消失——它们在语义空间中彼此很近。稀疏路恰好在这些点上强壮，密集路在表述变体上占优。两路是互补失效，不是相互替代。
>
> 融合我不用"归一化加权求和"，因为 BM25 分数无上界、随语料漂移，余弦相似度挤在 0 到 1 的窄区间，两者做归一化加权需要持续校准，稍有不慎就有一路被完全掩盖。我倾向 RRF 这种只吃排名的融合：不需要校准、抗漂移，代价是损失分数间距；如果需要更精细的阈值裁剪，再换回校准过的分数融合。
>
> 重排我会做，但设硬预算：候选从 50 降到 20，用蒸馏小模型，超时 200ms 未返回就降级为融合排名。而且上重排之前先验 Recall@50 是否达标（比如 ≥ 90%），否则重排只是在给一个已经漏掉答案的候选集做精装修。
>
> 上线后效果仍不达标，就按四层归因：Recall@50 看召回、Recall@8 看排序、人工抽检位置分布看上下文利用、最后才是模型可信度。哪一层掉了就修哪一层，不轻易得出"换更大的模型"的结论。

### 8. 面试官追问及回答要点

**追问**：RRF 的 `k` 怎么定？调大会发生什么？

**回答要点**：
1. `k` 是**抑制排名尾部影响**的平滑因子。`k` 越大，不同名次之间的分差越被压平（趋向"只要进入列表就同等计分"）；`k` 越小，头部名次的权重越突出。
2. `k = 60` 是原始论文给出的经验值并有抗排名抖动的作用，但**必须在自己的数据上做网格（如 10/20/60/100）并用 Recall@8 验证**，不要把它当成物理常数。
3. 注意 RRF 对弱路召回没有免疫力：如果多查询扩展产生了一路质量很差的候选，它同样会被平等计分。此时应使用加权 RRF 或先过滤弱路。
4. 出处：RRF 由 Cormack、Clarke、Buettcher 在 2009 年 SIGIR 论文《Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods》中提出，最初用于多路查询融合（本轮未核验原文，按公开引用的通用描述陈述）。

## 三、为什么要精选这道题

1. **它是 RAG 类问题里唯一能区分"做过"和"没做过"的题**。稀疏/密集的互补性几乎人人能背，但只有真排查过线上问题的人，才说得出"错误码在向量空间里会消失"这种具体到例子的失效模式。
2. **归因顺序是可迁移的通用能力**：先验召回再验排序，最后才怀疑模型。这条规则同样适用于工具调用失败排查、Agent 轨迹评测、以及任何多阶段流水线的问题定位。
3. **它同时考察成本意识与结果意识**：重排是"用数倍延迟买排序质量"的取舍，能不能给出硬预算与降级条件，是中高级的直接判据。
